## Execution and code ownership findings

The installed `nadi` CLI in `src/nadi/cli.py` currently exposes historical `prepare`, `train-risk`, `generate-hydraulics`, `run-demo` and `benchmark` routes. The authentic Xylem experiment is instead launched by standalone scripts. Thus a **single canonical CLI does not yet exist**. The README explicitly places authentic work first, while retaining a second historical pipeline and a simulated decision chain. This is a useful distinction, but it is not enforced by package entry points.

The experiment writes directly into `results/authentic_locked` via `mkdir(exist_ok=True)` and subsequent `to_csv`/`write_text`; it does not refuse to overwrite the currently named “locked” artifacts. Do not rerun it against that default output during the audit. A new run must use a fresh output directory and compare hashes/metrics before any migration.

The authentic result is a retrospective ranking over already collected EA surface-water outcomes. The denominator and selection process do not establish a prospective utility testing gain. The BWFLnet result is a separate hydraulic validation. There is no verified common event key joining these two evidence tracks.

## Material-domain and timing correction

The 14,069 raw records have determinand 2348 and the unit `NUMBER PER HUNDRED MILLILITRES`, but they do not all describe surface water. Material counts include 7,970 sea-water samples, 4,529 river/running-surface-water samples, 646 estuarine samples, 369 surface-drainage samples, 36 final-sewage-effluent samples and smaller groundwater/other categories. The 13,405-row processed table inherits this mix. In the 545-row locked period, 410 are river samples, 68 estuarine and 28 sea; the training period has 1,615 sea and 1,216 river rows. This is a substantial material and time distribution shift. The accurate dataset label is **EA environmental-water E. coli observations with mixed sample materials**. The dossier's unqualified “surface-water observations” wording requires correction.

Observed censored result values are `<10` (5,038), `<1` (5), `>10000` (18), `>100000` (23), `>1000000` (5), and `>9999999` (2). Their sides of the >=500 endpoint are unambiguous, so the inspected `parse_ecoli_result` implementation does not create ambiguous labels for these observed qualifiers. The endpoint is a project-defined high-count classification and is not a drinking-water safety threshold.

`site_rounds.py` uses collection date to decide when historical labels enter features. The raw table has `phenomenonTime` but no verified laboratory result-release timestamp. Thus same-date exclusion is implemented, while **real-time label availability for later days is not established**. This matters for any prospective forecasting claim. The downloadable-data script also calls its raw output immutable in its docstring but uses `out.write_bytes`, which would overwrite an existing path; the raw file must not be re-downloaded at its default destination during the audit.

## Further protocol findings

The unseen-site subgroup in the authentic experiment comprises 50 rows from 31 sites absent from model training. Its XGBoost F1 is 0.722222 and ROC-AUC is 0.704545, with specificity 0.181818. This is distinct from the 140-row physicochemical site-hash experiment, whose XGBoost F1 is 0.737430 and ROC-AUC 0.713453. Neither is a new-city or drinking-pipe transfer test.

The corrected simulated Net3 V5 benchmark (`results/locked/benchmark_v5_no_placeholders_summary.json`) attempted/evaluated 120 events, of which 76 were nonempty. SDAIF and adaptive Bayesian each have Coverage@3 = 0.614912; superiority is explicitly unsupported. The L-TOWN stress result has four nonempty hidden cases: SDAIF mean coverage 0.256548 versus 0.359226 for adaptive Bayesian and hydraulic-only. A separate Net3 unseen-source study records 12/12 false source attributions for SDAIF when the true source was absent from the enumerated reference sources. These are simulation findings, not microbiological evidence.

The current-sample `sampling_purpose` and `material` columns are categorical model features. They originate from the collected sample record. `material` may be knowable in advance for a registered monitoring site, but the audit has not established that `sampling_purpose` was fixed and available before every proposed test decision. It may encode follow-up or reactive sampling and is therefore a selection-context and prospective-availability risk. The Phase 6 leakage audit must test an ablation without this field and specify the allowed input contract.

## Phase 1 audit disposition

The major dossier claims and requested numeric values have been mapped to candidate code and artifacts.
