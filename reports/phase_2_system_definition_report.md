# Phase 2 system-definition report

**Files inspected:** Dossier sections 1–19 and appendices via the Word document/source builder; `README.md`; `src/nadi/cli.py`; authentic model, site-round, benchmark and policy modules; EA and BWFLnet reports; Net3 V5 and L-TOWN stress summaries; current provenance manifest; dashboard entry-point paths.

**Commands run:** Read-only source/result listings and content inspection; EA source/processed SHA-256 checks; authentic fresh-output reproduction; BWFLnet prediction arithmetic; material and qualifier counts. The latter checks were completed in Phase 1 and are the empirical inputs to this phase.

**Changes made:** Added `canonical_architecture.md`, `evidence_track_boundaries.md`, `canonical_entry_points.md` and this phase report. Existing source, data, results, dashboard and frozen-looking artifacts were not moved or rewritten.

**Tests and results:** The preexisting suite passed in the audit environment, and the authentic run reproduced byte-identical files in a new path. Phase 2 itself defines boundaries; its enforcement tests remain for Phase 7. The architecture names retrospective EA environmental-water testing priority as the primary empirical result and keeps observed BWFLnet pressure, simulated Net3/L-TOWN reach, telemetry and external transfer as distinct tracks.

**Failures/uncertainties:** No unified biological/network event dataset exists in the inspected artifacts. Historical EA result-release time and predecision availability of sampling purpose are unverified. `nadi` currently routes older workflows, while authentic Xylem uses standalone scripts. Default output paths can overwrite named locked artifacts. The dashboard's source-of-truth route has not yet been traced.

**Evidence status:** Canonical claim is supported only as a retrospective environmental-water ranking experiment from current processed data. Hydraulic state estimation is separately supported by stored real-network predictions. No biological pipe localization or prospective exposure reduction is established.

**Remaining risks and next-phase inputs:** Phase 3 must map imports, file reads/writes, duplicate algorithms, hidden fallbacks, dashboard consumers and versioned benchmark ownership. Only then can Phase 4 record safe migrations, and Phase 5 implement one guarded CLI.
